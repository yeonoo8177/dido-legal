dido 개인정보처리방침

시행일: 2026. 7. 25.

dido(이하 "서비스")는 이용자의 개인정보를 소중히 다루며, 아래와 같이 수집·이용합니다. 서비스의 핵심(사진 촬영·배경 제거·카드 제작·기록)은 이용자의 기기에서 처리됩니다. 로그인 전에는 사진과 카드가 기기에만 저장되고, 로그인하면 카드 본문, 재인코딩된 장면·누끼·뒷면·친구 누끼와 펫 이름·성장·급식·보상 기록이 아래와 같이 본인 계정의 non_location_v1 비공개 저장소에 자동 백업됩니다.

1. 기기에만 저장되는 것

로그인 전에는 촬영/선택한 원본 사진, 오려낸 이미지(누끼), 카드·메모와 펫 상태가 이용자의 기기에만 저장됩니다. 로그인하면 카드 본문과 재인코딩된 장면·누끼·뒷면·친구 누끼, 펫 이름·성장·급식·보상 원장이 본인 계정의 비공개 저장소에 자동으로 백업·동기화되며, 설정의 "백업"으로 직접 실행할 수도 있습니다. 지원 이미지는 방향을 픽셀에 반영하고 EXIF·GPS 등 내장 메타데이터를 제거한 PNG로 다시 인코딩합니다. 그러나 픽셀에 보이는 간판· 주소·랜드마크는 지우지 않으며, 메뉴명·메모에 직접 적은 상호·주소 같은 장소 단서와 함께 비공개 백업에 포함될 수 있습니다. 안전하게 디코딩할 수 없는 원본 컨테이너는 업로드하지 않습니다. 앱은 카메라 촬영 뒤 앱이 소유한 임시 캐시만 정리하며, 갤러리에서 선택한 원본은 삭제하지 않습니다. 로그인하지 않으면 사진·카드·펫 상태는 비공개 백업에 업로드되지 않습니다.

중복 경고용 sourceHash는 사용자가 고른 원본 바이트의 SHA-256으로 카드와 함께 기기에만 저장하고 계정 백업에는 넣지 않습니다. 원격 이미지 객체 이름에는 메타데이터 없는 PNG 바이트의 SHA-256 콘텐츠 해시를 사용합니다. 이 값은 sourceHash와 다른 결정적 콘텐츠 주소이며, 무작위·익명 식별자라고 보장하지 않습니다.

과거 앱 버전의 카드별 위치값은 startup에서 카드 row 내부의 로컬 전용 격리 영역으로 옮겨 일반 카드 화면·모델·이벤트·백업에서 보이지 않게 합니다. 이 값은 해당 카드 삭제 또는 계정 전체 삭제 때 row와 함께 삭제됩니다. 과거의 장소별 방문 키는 이와 별도의 로컬 방문 원장 격리 영역에 두며, 개별 카드 삭제로는 삭제되지 않고 회원 탈퇴나 전체 로컬 초기화 때 삭제됩니다. 둘 다 별도 법률 검토와 이용자의 명시적 선택 없이는 다시 사용하지 않습니다.

2. 외부로 전송되는 것

  • 생성형 AI 이미지 처리: 현재 릴리스에서는 AI 이름 추천과 AI 변형 이미지 기능을 사용할 수 없으며, 디저트 사진이나 캐릭터 이미지를 Google(Gemini) 등 생성형 AI로 전송하지 않습니다. 제공자의 연령 및 API Client 대상 약관, 적법한 처리자 계약, 유료/no-training·사람 검토 조건, 국외이전과 스토어 신고를 모두 검토·승인한 별도 릴리스에서만 재검토합니다. 유료 또는 no-training 조건만으로 미성년자 관련 제공자 약관 문제가 해소되는 것은 아닙니다.
  • 위치·장소·지도: 현재 배포판은 운영체제 위치 권한을 선언하거나 요청하지 않고, 현재 위치 취득·역지오코딩·근처 계산·가게 후보 검색· 개인 지도를 실행하지 않습니다. 새 카드의 구조화된 위치·가게 필드, 가명 이벤트, 비공개 백업·복원에는 앱이 자동으로 얻은 좌표·위치 파생 주소·가게명·제공자 장소 ID 또는 장소와 날짜를 결합한 방문 원장을 넣지 않습니다. 다만 이용자가 메뉴명·메모 같은 자유입력란에 상호나 주소를 직접 적으면 그 내용은 카드 본문으로 기기에 남고, 로그인 시 비공개 백업될 수 있습니다. 사진의 내장 메타데이터는 제거하지만 픽셀의 간판· 주소·랜드마크도 재인코딩된 비공개 사진에 남을 수 있습니다. 이 픽셀· 자유입력 단서는 가명 이벤트·사업 분석에는 사용하지 않습니다. 위치를 포함할 수 있는 기존 원격 legacy backup은 현재의 non_location_v1 백업이 자동으로 읽기·삭제·이전하지 않습니다. 일반 동기화가 legacy를 정리하지 않는 것과 달리, 명시적 회원 탈퇴는 해당 UID 아래의 현재·과거 형식 백업 전체를 삭제합니다. 이 경계는 환경변수·저장 설정·API 키·서버 응답· 원격 설정으로 활성화할 수 없습니다.
  • 가명화 기록 제공(선택): 현재 배포판은 법률·국외이전·스토어·실기기 검증이 끝나지 않아 서버 기록 수집을 사용할 수 없고 이벤트 journal이나 전송 대기열도 만들지 않습니다. 따라서 위치·장소뿐 아니라 메뉴명, 맛·멋·분위기 점수와 선택형 키워드도 현재 서버로 보내지 않습니다. 이전 버전에서 적법하게 수집된 서버 원시 이벤트나 검증 메타데이터가 실제 남아 있는 경우에만 아래의 보유·철회·삭제 절차가 적용됩니다. 현재 빌드는 새 내부 분석·집계도 만들지 않습니다. 향후 수집 가능한 버전은 새 고지에서 항목·목적·보유기간·국외 처리와 위치정보법상 지위를 다시 밝히고 별도 새 동의 revision을 받습니다. 기존 선택, 과거 카드, 로컬 격리값 또는 legacy backup을 근거로 소급 수집하지 않습니다.
  • [선택] 인구통계(연령대·성별): 현재 배포판은 서버 기록 수집이 비활성이라 연령대·성별 구간을 전송하지 않습니다. 향후 기능을 제공하는 경우에는 만 14세 이상 이용자에게 가명 기록 제공과 구분되는 별도 동의를 받고, 생년월일·정확한 나이 원값은 저장하지 않습니다.
  • 네트워크 남용 방지: 서버 수집·삭제, 구매 검증 등 쿼터가 적용되는 Edge 요청에서는 게이트웨이가 확인한 요청 출발지 IP 주소를 dido의 Edge 코드가 요청 처리 중 메모리에서 일시적으로 읽고 정규화한 뒤, 서버 비밀키 HMAC으로 경로별 호출자 버킷을 만듭니다. dido의 쿼터 데이터베이스에는 원본 IP 주소 대신 64자리 HMAC 버킷, 요청 경로, 시간 구간과 횟수만 저장되며, 원본 IP 주소·요청 본문·인증 토큰·사진· 좌표·구매 영수증을 쿼터 행에 기록하지 않습니다. 시간 구간 시작 후 2일이 지난 버킷은 매일 삭제합니다. 이 버킷은 남용·비용 제한에만 사용하고, 이용 분석·프로파일링·맞춤화·사업용 집계에는 사용하지 않습니다. 현재 소스에서 닫힌 카카오 장소 검색과 생성형 AI 중계는 dido의 본문 파싱·쿼터·외부 호출 전에 거부됩니다.
  • 로그인·백업·구매 검증: 카카오는 로그인 과정에서 이메일·닉네임·프로필 이미지를, Apple은 이메일·이름(fullName)을 제공할 수 있습니다. Supabase 계정 UID와 인증 메타데이터는 인증·비공개 백업에 사용됩니다. Apple 이름은 현재 앱 데이터베이스에 별도로 저장하지 않습니다. Apple 로그인이 연결된 계정을 iOS에서 탈퇴할 때에는 삭제 요청을 위해 새로 받은 일회용 authorization code와 앱이 만든 무작위 nonce를 서버가 받습니다. 서버는 code를 Apple 토큰으로 교환하고 토큰의 서명·발급자·대상·nonce 해시·계정 subject를 확인한 뒤 교환된 토큰을 즉시 폐기합니다. code·nonce·교환 토큰은 데이터베이스나 로그에 저장하지 않고 해당 요청을 처리하는 동안에만 사용합니다. 자동 교환·검증·폐기를 먼저 시도하지만 실패하거나 사용할 code/token이 없는 경우에도 dido 계정·비공개 백업·계정 귀속 원시 이벤트 삭제는 계속합니다. 이때 삭제 완료 뒤 Apple 설정 또는 account.apple.com에서 Apple 연결을 직접 해제하도록 안내합니다. 삭제 완료 증명에는 not_applicable, revoked, manual_required 중 결과만 남기며 Apple code·token·nonce·subject는 저장하지 않습니다. 비공개 백업에는 카드 본문, 재인코딩된 장면·누끼·뒷면·친구 누끼와 펫 이름·성장·급식· 보상 원장이 포함되지만, 앱이 자동 취득한 위치 필드와 별도 장소-일자 방문 원장은 제외됩니다. 구매·복원 시 스토어 영수증을 로그인 세션의 인증 헤더와 함께 Supabase 구매 검증 함수에 전송하므로 계정과 연결될 수 있으며, iOS 영수증은 검증을 위해 Apple에 전달됩니다.

3. 처리 위탁 · 제3자

서비스 제공을 위해 다음에 처리를 위탁합니다: 카카오(로그인), Supabase, Inc.(미국 사업자; 계정·non_location_v1 비공개 백업·구매 영수증 검증과 실제 남은 과거 원시 이벤트의 삭제), Apple(로그인·iOS 영수증 검증·Apple 연결 계정 탈퇴 시 일회용 code 교환과 토큰 폐기). 현재 릴리스는 운영체제 위치 권한, 역지오코딩, Kakao/MapKit 장소 후보, 개인 지도 또는 위치 이벤트를 실행하지 않고 이벤트용 Google Play Integrity·Apple App Attest도 호출하지 않습니다. 또한 현재 릴리스는 Google에 생성형 AI 처리를 위탁하지 않으며, AI 중계 함수도 소스 수준에서 닫혀 있어 환경변수나 API 키만으로 사진을 전달할 수 없습니다. 운영 프로젝트의 실제 주 데이터 리전, 하위처리자, 지원 접근 경로와 국외 처리·이전의 국가·방법·시점은 출시 전에 Supabase 콘솔·계약 자료로 확인하여 본 방침과 스토어 신고에 확정 고지합니다. 이 확인과 고지가 끝나기 전에는 해당 서버 수집 기능을 운영하지 않습니다. Supabase, Inc.는 미국 사업자이므로 운영·지원 과정에서 국외 처리가 이루어질 수 있습니다. 각 사업자는 위탁 범위에서만 정보를 처리합니다.

현재 외부 데이터셋·수신자 계약·전달 경로는 열려 있지 않으며, 현재 배포판은 위치·장소·메뉴·평점 이벤트를 새로 수집하지 않습니다. 향후 내부 분석 또는 제3자 제공을 시작하려면 별도 새 동의 revision, 수신자· 목적·보유기간 계약, 법률·개인정보·보안·품질·스토어·실기기 검토와 데이터베이스 승인 절차가 필요합니다. 기존 선택·카드·격리값·legacy backup에 소급하지 않습니다.

4. 보유 및 이용기간

아래 기간은 현재 서버 구현의 최대 상한입니다. 처리 목적 달성, 적법한 철회·삭제·처리정지 요구, 회원 탈퇴 또는 법령상 더 짧은 기간이 적용되면 먼저 삭제하거나 처리를 중단합니다.

구분보유기간·삭제 기준
기기 데이터·non_location_v1 계정 비공개 백업 기기 데이터는 이용자가 직접 삭제할 때까지, 계정 백업은 회원 탈퇴할 때까지. 카드 위치 격리값은 해당 카드 또는 계정 삭제 때 삭제하지만, 별도 방문 원장 격리값은 개별 카드 삭제로 지워지지 않고 회원 탈퇴나 전체 로컬 초기화 때 삭제합니다. 원격 legacy backup은 일반 동기화가 읽기·삭제·이전하지 않지만 회원 탈퇴는 UID 아래의 현재·과거 형식 백업 전체를 삭제합니다. 다중 기기에 안전한 서버 세대 CAS와 유예 GC를 도입하기 전에는 카드 삭제·교체 뒤 manifest가 더 이상 참조하지 않는 콘텐츠 주소형 원격 이미지 객체도 비공개 저장소에 회원 탈퇴 때까지 남을 수 있습니다.
기존 선택 제공 원시 이벤트·이벤트 수신 영수증·완료된 무결성 요청 현재 빌드는 새 원시 이벤트를 만들거나 보내지 않습니다. 이전 버전에서 적법하게 수집된 기존 수집분이 실제 남아 있는 경우에만 최대 12개월이며, 서버 수신 시각, 이벤트 시각 및 카드의 경험일/생성일 경계를 확인하여 매일 삭제합니다. 12개월 삭제 작업이 36시간 안에 성공하지 않으면 새 원시 이벤트 수집을 중단합니다.
무결성 검증 임시 상태 만료된 미처리 challenge·요청은 만료 후 1일 경계, 처리된 challenge는 처리 후 7일 경계, 폐기된 App Attest 키는 폐기 후 30일 경계에서 매일 삭제합니다. 장기간 사용되지 않은 활성 키와 완료 요청은 최대 12개월 경계에서 삭제합니다.
